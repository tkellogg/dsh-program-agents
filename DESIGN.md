# Program agents v0.1

A DSH plugin for supervised Node programs, not an RLM/REPL. No edits to DSH core, no execution-state durability, no implicit model loop. Current integration target DSH 0.2.1-rc.2. Separate child processes isolate crashes/event-loop stalls, not a security sandbox; only configured/trusted program entrypoints may launch. A process is host-owned, may outlive spawning tool call, and is stopped/revoked when supervisor/plugin goes away. Parent identity captured at launch. No automatic restarts or effect retries. Explicit restart only after previous generation process-group exit. If exit cannot be proven restart fails closed. Same logical program id, incremented generation. Bounded process stdout/stderr/inboxes/history, IPC limits and per-call deadlines. Read-only UI displays HTTP(S) links, never embeds or fetches arbitrary pages; generation-bound service links become unavailable on terminal state. Host capabilities use typed JSON boundaries, explicit allowlists, generation cancellation. Parent notifications are explicit, bounded/rate-limited; no prompt flooding for status/log updates.

## Shared runtime contract (implement under src/runtime and src/sdk)

Export from src/runtime/index.ts:
- `ProgramSupervisor`, `CapabilityRegistry`, `ProgramError` and public types from src/types.ts.
- Constructor options `{ programs: Record<string, ProgramDefinition>, capabilities?: CapabilityRegistry, onParentMessage?: (ownerId:string, message:JsonValue, run:ProgramSnapshot, signal:AbortSignal)=>Promise<void>, onEvent?: (event:ProgramEvent)=>void, maxRuns?:number, maxHistory?:number, startupTimeoutMs?:number, stopTimeoutMs?:number, callTimeoutMs?:number }`.
- `ProgramDefinition { entry:string; cwd?:string; args?:string[]; env?:Record<string,string>; allowedCapabilities?:string[] }` configured trusted entrypoints only. Do not inherit all host env secrets; minimal environment + explicit env.
- `start({program:string, ownerId:string, input?:JsonValue, label?:string}, signal?:AbortSignal):Promise<ProgramSnapshot>` return after SDK hello (not main completion). Program ownerId is opaque session id, never child-selected.
- `list(ownerId?:string):ProgramSnapshot[]`, `get(id:string,ownerId?:string):ProgramSnapshot`, `send(id:string,ownerId:string,body:JsonValue):Promise<void>`, `stop(id:string,ownerId:string):Promise<ProgramSnapshot>`, `restart(id:string,ownerId:string):Promise<ProgramSnapshot>`, `dispose():Promise<void>`; UI uses owner-scoped operations.
- Snapshot `{id, generation, program, ownerId, label, state:'starting'|'running'|'blocked'|'stopping'|'stopped'|'completed'|'failed', status?:string, pid?:number, startedAt:string, endedAt?:string, error?:string, logs:Array<{sequence:number,stream:'stdout'|'stderr'|'system',text:string}>, resources:Array<{id:string,title:string,url:string,available:boolean}>, messages:Array<{direction:'parent'|'program',body:JsonValue,at:string}>, result?:JsonValue }`.
- Event `{type:'changed', run:ProgramSnapshot}`; coalesce/bound observers no unbounded raw token streams.
- CapabilityRegistry `.register({name:string,description:string, inputSchema?:JsonValue, handler:(input:JsonValue,context:{run:ProgramSnapshot,signal:AbortSignal})=>Promise<JsonValue>}):()=>void`; `.list()` metadata; only run's configured allowlisted capabilities available. Include runtime intrinsic parent.send, status.set, resources.publish/unpublish exposed via SDK; register model/tool methods in host, NOT runtime. Validate protocol JSON and named method boundaries. No caller-selected identity.

SDK exports from src/sdk/index.ts:
- types `ProgramContext`, `ProgramMain`, `JsonValue`.
- `runProgram(main:ProgramMain):void` optional standalone entrypoint uses IPC process bootstrap (or runtime imports module default using bundled bootstrap). Choose one consistent approach and document it.
- ProgramContext `{ id:string,generation:number,input:JsonValue,signal:AbortSignal,inbox:AsyncIterable<{body:JsonValue}>, parent:{send(body:JsonValue):Promise<void>}, status(state:'running'|'blocked',detail?:string):Promise<void>, resources:{publish({id,title,url}):Promise<void>,unpublish(id):Promise<void>}, capabilities:{list():Promise<CapabilityMetadata[]>,call(name:string,input:JsonValue):Promise<JsonValue>}, models:{call(input:JsonValue):Promise<JsonValue>}, tools:{call(name:string,args:JsonValue):Promise<JsonValue>} }`.
- Child bootstrap imports default async function `main(ctx)`, no REPL/eval. Prefer bootstrap path built dist/runtime/bootstrap.js. Supports Node native JS and strip-types TS (Node>=22.18); pinned node recommendation current26. Treat SDK connection only child with actualIPC.

## Host plugin (parent task)

Host service programAgents owns supervisor and configured program definitions. Register model-facing tools program_start/list/send/stop/restart. Access uses exact exec.agent's session id. Model capability calls DSH llm with explicit allowlisted routes and provider-held secrets never exposed to child. Tool capability calls DSH tools public execution with fresh execution identity; never reuse expired spawning exec token, validate owner is live, preserve permission/approval pipeline and durable nested tool events if supported. Fail closed if authority cannot safely be reconstructed. Generic capability extension via public registry. Parent messaging uses live owner inbox/steer (not fake child identities). Lifecycle/effect records in bounded private plugin JSONL (never custom third-party SessionEventMap records); terminal context notices may be injected into the parent, not application state replay. DSH host/UI RPC surface can use registered authenticated web routes or typert descriptors; do not add unauthenticated arbitrary launcher endpoints. Prefer DSH gateway RPC, authenticated carrier. Plugin restrictions: trusted program execution requires explicit config allowlist; parent tools cannot supply arbitrarycode/command or secret env. No sandbox claims. UI cannot cross-owner controls.

## Web plugin (independent task)

Use DSH client contribution slots (discover actual APIs) and one host/client bundle declaration. Host publishes API contract for UI below; if unavailable show unavailable state. JS browser code consumes existingauthenticated DSH remote transport, not customcredentials. Show program cards (state/status/generation), messages/logs, resources external links with rel=noopener noreferrer. Stop/restart/send controls with pending/error; no arbitraryURLfetch/iframe. Surface parent session scoped program list in conversation slot or plugin page with selectedsession; no globalcross-sessiondata leak. Runtime host and UI protocol agreed next; tests mock transport and verify link scheme safety, stale-resource disabling and state controls.

No Python; no implicit code repair, no automatic replay, no claim of native subagent tree continuation until public integration verified. Parent supervises through explicit program tools and events.
